## Limits that the proof text states itself

- The proof text is a conditional composition. In its words (paragraph P003): "This text does not itself certify its imported premises or issue independent acceptance of the complete assembly; that assessment remains required."
- Execution authenticity is an assumption. Paragraph P037: "Authentic execution on the pinned stable checkout is an explicit provenance assumption, not a mathematical property of the recorded hashes." Paragraph P035: "merging agreeing slices does not replay their arithmetic or authenticate them."
- Paragraph P116 lists everything an independent assembly must bind and ends: "A printed status, PASS summary or this manuscript cannot discharge a missing antecedent."
- Uniqueness of the packing is not claimed.

## The capture computation

- Capture: 98 numeric statements, 1,728,000 rows for each of the two checkers. The edition carries one fresh computation by each checker (Python and Node.js) on inputs without free text, in 1,152 slices. Before release the project compared it row by row with stored earlier executions, through a published hash map and name map: 1,728,000 rows per checker, 0 mismatching. The earlier executions are not carried; the records of that comparison are. The merge of the slices is structural and does not recompute the charge inequalities; the producers' public check `provenance` decides every stored row again from the numbers recorded in it.
- **Two runtimes.** 1,041 selected slices ran on Python 3.12.14 / Node.js v24.19.0 and 111 on Python 3.11.17 / Node.js v22.22.0.
- **What was not recorded of them.** Values of environment variables were not recorded per attempt: each of the 1,152 slice records holds a list of names (`environment_names_set`) and no value. The value `NODE_OPTIONS=--max-old-space-size=8192` (a heap limit, no file) on the second runtime was observed afterwards, on one machine; it is not part of any attempt's record. It was observed by the audit side of the project, not by the producers. The Node.js binary is identified by its version string only, not by a digest.
- What the records do hold: for each slice run the launcher recorded the names of the environment variables of a fixed family that were set. `NODE_EXTRA_CA_CERTS` and `NODE_PATH` are recorded in all 1,152 selected slice runs; `NODE_OPTIONS` and `PYTHONUNBUFFERED` only in the 111 runs of the second runtime. The environment was inherited, not scrubbed. All selected slices ran on Linux x86_64, with numpy 2.0.2, numba 0.60.0. The same holds for the Python interpreter and the libraries as for Node.js: versions are recorded, binaries are not authenticated.
- **The merges ran on a third runtime.** All 98 merges were made on one runtime (Python 3.9.6 / Node v25.6.1 on Darwin arm64: 98, from the 98 merge records); this is also the runtime of the machine on which the edition was assembled and checked. A merge is structural: it does not recompute a row.
- **Three sentences in the header of the launcher say slightly more than its code does** (`CAP/checker_sources/slice_run.sh`; the file is frozen and was not reopened for this). (1) "no record is written" for exit code 1: if the error comes after the record is in place, a complete record exists and the process still exits 1; exit codes 126 and 127 are not listed. (2) The list of recorded environment names is a fixed family (`PYTHON*`, `NUMBA_*`, `NODE_*`, `*_NUM_THREADS`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `DYLD_*`, `BASH_ENV`, `CDPATH`), not every variable that can change how a program runs. (3) The lists "Variables read by this script" and "Programs started" omit `CDPATH` and the utilities `mkdir`, `dirname`, `basename`. None of the three changes a result.
- **Two document paths in the comments of the capture checkers name files that are not carried** (`cloud/analysis/CLASS_FORMAT.md` and `cloud/analysis/RESTRICTED_CHECKER.md`). No file is carried at either path. A file named `CLASS_FORMAT.md` is carried at another path (`research/finishing-threshold-goal-20261007/current-author-20261012t/fifth-order-20261010/public-edition-round2-20261011/records/round2/window-capture/class-capture-audit/checkers/independent-review/inputs/CLASS_FORMAT.md`); its bytes differ from the project's present file at the named path, so it is another version of that document. The checker sources are frozen; their bytes were not changed.
- **Which Node.js checker.** The checker of record is `verify_classes_wb.js` (SHA-256 `7f6b234768f812b7...`). Stored slices and receipts print "node verify_classes.js" as the implementation string; it is the same file (`CHECK.md`, last part).
- **Selected attempts.** For each planned slice the merge takes the lowest-numbered attempt that passes every test of the merge script. 867 of the 1,152 selected slices are first attempts (a1: 867, a2: 272, a3: 12, a4: 1). Attempts that were not selected, and the earlier executions, are not carried.

## Other limits

- **One platform.** The project ran `check.py` on this edition on one platform only: macOS 27.0.1 (Darwin 27.0.0, arm64), CPython 3.9.6, Node.js v25.6.1, SymPy 1.14.0. It also ran the full check once under CPython 3.12.14 on the same machine. Other platforms are untested (`CHECK.md`).
- **The name of the root folder must not occur twice in its own path.** The producers' runner splits a path at the first occurrence of the name of the root folder. If a folder higher up has the same name, it would build wrong paths. `check.py` tests this (`root-name`) and reports a failure with a message; rename one of the two folders.
- **Root admission.** For the premise ROOT_ADMISSION the proof text has the paragraphs P005, P043, P044, P045, P059, P060, P073, P078, P079. The exact computation is `PKT/scripts/run_adm.py` with `adm.py` (public check `admission`). `F1_PROOF.md` is, by its title, about the loose-role identities ("F1 repair: actual off-wall loose-role identities precede angle classification"). No separate written proof of the admission geometry is bound to this premise. The reviews bound to it are the two reports named in `READING_ORDER.md`, part 3; no other independent review is. One step, a bound on the side direction of a square whose centre is near a wall, is stated only as a comment and an assertion in `run_adm.py`, lines 17 and 18, and not in the proof text. See `KNOWN_ISSUES.md`, item 1.
- **A partial run is not a PASS.** `check.py` ends with `CHECK RESULT: PARTIAL` when only one level or one check was run, when checks were not run because large files are absent, or when a check was stopped by the CPU limit of its own script or by the time limit of the producers' runner (`CHECK.md`).
- **A slow machine cannot finish some public checks.** 15 of the 31 public checks run a script of the producers that sets a CPU limit for itself (`resource.setrlimit(RLIMIT_CPU, ...)`), and the producers' runner sets an alarm of 570 seconds of wall time around the script of every check. These limits stand in files that hashes bind; `check.py` cannot change them, and `--timeout-scale` does not reach them. On a slow machine a check can use up its limit before it has finished. `check.py` then reports that check as `TOO-SLOW`, names the limit that stopped it, and ends `PARTIAL`: the check was not carried out on that machine, and no inequality failed. On the build machine every check stayed inside its limit; a slower machine may not. `CHECK.md` has the table of limits and times.
