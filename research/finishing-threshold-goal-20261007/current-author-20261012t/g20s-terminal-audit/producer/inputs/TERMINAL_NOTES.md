## 4. Soundness review of the re-instantiation

Question: is anything in `PROOF.md`, `README.md`, `DERIVATION.md` or the code valid only for the original
box, and does any check become weaker?

- **S1. Hard-coded `padded` box in `bridge.py` L198.** A second copy of the slider box. Changed in lockstep
  with `uniform.py` L80 (both lines are generated from the same six fractions). `verify.py` L23-26 compares
  it with `rigidity.initial()`; a mismatch raises. Dealt with: changed, cross-check passes.
- **S2. Unpadded lower end of a** (`rigidity.py` L26 `lo if w==2 else lo-PAD`; `bridge.py` L189, L198).
  Justified only by the physical fact a* >= 0 (reach of square 2 is at least 1/2, S <= S*). It is valid
  exactly when the box's a-interval starts at 0. A sub-box with a_lo > 0 would need a_lo - pad; the bridge
  would refuse such a sub-box (a* = a - (p_2x + 1/2 - S*) falls below a_lo by 4.3e-17), so this fails closed.
  Dealt with: all instances have a_lo = 0; `make_instance.py` refuses anything else. No a-split was needed.
- **S3. The tight-row roster depends on the slider box, and the option audit accepts a pair that has lost
  its rows.** `root_geometry.tight_labels()` (L85-90) keeps what `uniform.model` keeps on the instance's
  slider box. If a second separating option becomes feasible for a unique-owner pair, `uniform.model` drops
  the pair (L261-262), its `pair:` label disappears, and `rigidity.option_audit` (L88-92) then expects
  "both owners with the reference (axis index, sign)". For (5,11) and (3,13) the competing option happens to
  have the same (axis index, sign) for the other owner (normal +x of square 5 or 3), although these two
  normals are not parallel. So the audit prints PASS with 19 pairs while the pair has no row at all.
  This is **safe** (dropping rows only enlarges the feasible set; observed consequence: ratio stays 1, no
  theorem), but "option audit PASS, 19 pairs" alone is not evidence that all 19 pairs are in force.
  Observed: b_hi = 1/4 and 7/20 (51 labels, `pair:5:11:11:3:0` missing), z_lo = -62/100 (51 labels).
  Dealt with: `tools/roster_check.py` confirms for every delivered instance that the roster is exactly the
  original 52 labels with 11 unique and 8 parallel pairs; `verify.py` reports `identities: 52`.
- **S4. Branch table in `root_geometry.row`** (L70-73): `tau = 0` for (1,3), (1,5), (2,6) and `branch = -1`
  only for (2,6). The zero is a symbolic identity at slider 0 (checked, `rigidity.py` L61-64) and the slider
  part is carried separately in `tauw`, so it holds for every a. The hard-coded branch is not trusted:
  `rigidity.model` L121-123 evaluates tau on the whole (never narrowed) padded slider box in every round and
  raises if it leaves the branch or reaches absolute value 1. Intervals on each instance: `logs/roster.json`
  (box-relaxed: (11,12) in [0.006839, 0.206839], (13,14) in [0.005576, 0.205576], (2,6) in [-0.25, 0]).
  Limits: a_lo >= 0, b_lo >= -0.0568, z_hi <= 0.0806, a_hi < 1.
- **S5. "Base gaps vanish identically along sliders".** Proved symbolically per retained label, for all real
  slider values (the gap is affine in the sliders with slope checked to be 0). Not box-dependent. What is
  box-dependent is whether a zero-gap row is a necessary condition; that is the option audit (re-run).
- **S6. Remainder D, coefficient suprema, McCormick rows, slider-vertex maxima.** All recomputed from the
  current bounds; no stored number is reused. A hand re-derivation of the two first-order row types
  (unique owner: `D*Wo^2/2 + Wo*dr + V*Eta^2/2`; parallel faces: the formula of PROOF section 5) found
  the error terms of the code correct for an arbitrary slider range. The only conditions on the slider
  range are: the option audit, fixed sign and abs(tau) < 1 for parallel pairs.
- **S7. Side floor, normalisation `-1 <= s <= 0`, final step.** Use square 8 only. Independent of sliders.
- **S8. Numbers in `PROOF.md` that are specific to the original box**: 11 rounds / 3,432 objectives,
  5.518e-5, the box B+, 4 rounds / 368 objectives, the table of ratios. They are outputs, not premises;
  each instance has its own (`proof-receipt.json`).
- **S9. Codex's wider tubes A (0.08, 0.03) and B (0.01, 0.10) are not re-instantiated by the chain above.**
  Their certificates (`p_pos08.json`, `p_a10.json`, `capture.json`) were produced on the original slider
  box. Section 7 has what was re-run with the unchanged `quadratic.py` on the relaxed box.
- **S10. No check is weakened.** The checker code is byte-identical except the two constant lines. The
  bridge's inclusion test now tests against a larger box, and the rigidity proof is done on that same larger
  box; `verify.py` enforces that they are equal.
- **S11. Discovery vs proof.** `tools/probe.py` and `tools/probe_quadratic.py` (slider box supplied by a
  monkeypatch) are exploration only. Every delivered terminal instance is a real source copy replayed by the
  unchanged `verify.py`. The three wide-entry certificates were proposed by `probe_quadratic.py` and then replayed
  inside the real instance tree by Codex's `quadratic.py --check` (which rebuilds every model from the tree's own
  files; a certificate made for another box would fail its model digests).
- **S12. What is not independent.** Producer and checker are Codex's code; the analytic lemmas are hand
  proofs. The additions made here are exact bookkeeping checks (`composition_check.py`, `roster_check.py`,
  `handoff_check.py`) and float diagnostics (section 8), not proofs of the lemmas.
- **S13. `a >= 0` in the rational frame is a hypothesis of Codex's finite stage, and it is not automatic from
  `S <= Sref`.** The stored `p_2x + 1/2` is `Sref - 5.17e-18`. For a feasible configuration with `S <= S*` it is
  automatic because `S* < p_2x + 1/2` (obligation (1b), margin 4.32e-17, checked exactly). This obligation is not
  checked anywhere in Codex's code. The earlier wording "automatic from S <= Sref" was wrong and is
  corrected in every README.
- **S14. Wide entries (quadratic contractor).** `quadratic.py` has no slider constant; it loads the instance's
  `uniform.py`. Its slider-dependent quantities are recomputed from the bounds (L85 `cmax`, L93 and L119 `D`, L115
  the interval of `y` with `tauw`, the guard `Bmax < 1` at L123, the product rows L140-151). Its second-order
  parallel rows use the secant of the absolute value (L116-118) and need no fixed sign. The hand-over step is
  `tools/handoff_check.py`. Caveat: Codex's independent re-implementation `audit.py` covers the original box only.
- **S15. Side floor at position radius exactly 1/50.** Square 8's stored `p_8x + 1/2` is also `Sref - 5.17e-18`,
